# Agent Handoff Spec – 방탈출 리뷰 앱 (v1)

> 목적: **다른 개발 에이전트가 해석 없이 구현 가능한 단일 진실 소스(SSOT)**
> 범위: v1 MVP (iOS/Android, 지인용)

---

## 0. TL;DR (Quick Start)
- 한 줄 정의: **내 방탈출 기록장**
- 플랫폼: iOS / Android (웹 기반 + 앱 패키징)
- 리뷰 유니크: **방(테마)당 사용자 1개 리뷰 (DB 강제)**
- 기본 공개: **그룹 전체 공개**
- 링크 공유: **v1 포함 / 로그인 필요 / `/share/:token`**
- 태그: **고정 태그 12개 + 기타 1개 직접 입력**

---

## 1. PRD (Product Requirements)

### 1.1 문제 정의
- 방탈출 경험은 누적되지만 기억은 흐려짐
- 기존 플랫폼은 광고/랭킹 위주로 개인 기록에 과함
- 지인끼리만 참고할 수 있는 정제된 기록 도구 필요

### 1.2 목표
- 플레이 직후 **1~2분 내 리뷰 기록**
- 나중에 다시 봐도 **방 간 비교가 쉬움**
- 불특정 다수가 아닌 **지인 그룹 공유**

### 1.3 비목표(v1)
- 공개 랭킹, 댓글/좋아요, 예약/결제 연동

### 1.4 성공 기준
- 리뷰 작성 완료율 ≥ 90%
- 링크 공유 열람 성공률 ≥ 99%

---

## 2. APP_FLOW (화면/UX 플로우)

### 2.1 라우트
- `/` : 리뷰 목록
- `/review/new` : 리뷰 작성
- `/review/:id` : 리뷰 상세
- `/room/search` : 방 검색/등록
- `/share/:token` : 링크 공유 열람 (로그인 필요)

### 2.2 리뷰 목록
- 노출: **총평 별점 + 한줄평 + 지점/테마 + 지역**
- 필터 우선순위: **지역, 평점**

### 2.3 리뷰 작성 UX
- 상단: 총평 별점(필수) + 한줄평(100자)
- 중단(접힘): 보조 지표 6개(1~5)
- 하단: 방문 메타 / 본문 / 사진
- 기본 공개: 그룹 전체

---

## 3. REVIEW_FORM_SPEC (작성 스펙)

### 3.1 요약(필수)
- 총평 별점: 1~5
- 한줄평: ≤100자

### 3.2 보조 지표(1~5)
- 퍼즐 퀄리티
- 스토리/연출
- 장치/세트 퀄리티
- 공포도
- 퍼즐 난이도
- 클리어 난이도

### 3.3 방문 메타
- 성공/실패 (필수)
- 남은 시간(분) (선택)
- 인원 수 (필수)
- 장르/테마: 고정 태그 멀티 + 기타 1개
- 재방문 의사 (Yes/No)

### 3.4 본문/미디어
- 본문: ≤3000자
- 사진: 1~3장 (선택, 강유도)

## 4. DATA_MODEL (요약)

### 4.1 핵심 제약
- `reviews` unique: **(user_id, room_id)**
- `rooms` unique: **(vendor_name, theme_name, region)**

### 4.2 태그(고정)
- 공포, 감성, 추리, 스릴러, 코믹, 액션,
- 잠입/미션, 판타지, 어드벤처, 미스터리, 드라마, SF
- + `custom_genre` 1개

---

## 5. SECURITY_RLS (정책 요약)

- 작성자: 리뷰 CRUD 가능
- 그룹 멤버: `visibility=group` 조회 가능 — v1 구현: `auth.uid() IS NOT NULL` (로그인 사용자 전체)
- private: 작성자만
- link: **로그인 사용자만 / RPC로 조회**

---

## 6. LINK_SHARING

- URL: **`/share/:token`**
- 동작:
  1. 리뷰 `visibility=link` 전환 시 `share_token` 발급
  2. 링크 접근 → 로그인 확인
  3. `get_shared_review(token)` RPC 호출

## 7. DECISIONS (결정 로그)

- 리뷰 단위: v1 방 단위 1개 (DB 강제)
- 재방문 가능성 낮음 → 방문 테이블 v1 제외
- 링크 공유 v1 포함 / 로그인 필요
- 태그는 시스템 고정 + 기타 1개
- v1 그룹 정의: **로그인한 전체 사용자 = 단일 전역 그룹** (초대 기반 아님). UI 라벨은 '회원 공개', DB 값은 `visibility='group'` 유지
- v2 디자인 시스템 도입 (PR #32~#39): "노트앱 정돈감 + 방탈출 미스터리" 톤. ink 11단계 그레이 스케일 + paper(#f4ede0) + brand 액센트. Pretendard + JetBrains Mono. 기존 `--color-*` 토큰은 별칭으로 유지해 점진 마이그레이션. 다크 hero / 모노 시리얼 / 스크래치 스포일러 / 시각 메타가 핵심.
- 재방문 의사 라벨: SSOT §3.3은 "Yes/No"였으나 UI는 토스 톤 카피로 "다시 가요/충분해요" 사용 (PR #39). DB 값(`would_revisit boolean`)은 그대로.
- 서비스 워딩 통일: "업체" → "지점" (PR #40). DB 컬럼명(`vendor_*`)·코드 식별자는 영문 그대로, 사용자 노출 텍스트만 변경.
- v3 밝은 자연 톤 리톤: v2의 "차가운 ink + 파랑 brand + 다크 hero"를 전면 전환. 베이스는 **클린 화이트**(--color-bg #faf8f8, surface 순백 — 누런 베이지·웜 타페 시안은 탁해서 기각), 주조색은 **딥 틸(#11867a)** (핑크 메인 시안은 사용자 기각 — 핑크는 등급 포인트로만), hero는 다크 블록 대신 **밝은 소프트 민트(#ecf7f5, --hero-* 토큰)**. 등급 트리오는 글자 그대로 **꽃길=핑크(#ec6f9b) / 풀길=초록(#7cb15c) / 흙길=갈색(#b3865c)**, 단계별 3톤(기본/strong/soft). 다크 컨트롤(FAB·활성 칩·제출 버튼·토글 활성)은 브랜드 핑크로, 성공/실패 뱃지는 밝은 soft 톤으로. 하드코딩 옛 파랑(#4a90d9)은 brand 토큰으로 치환. 헤드리스 브라우저 스크린샷으로 홈/전체/상세/작성/검색 화면 검증 완료.
- 여정 선 확장 전략: 기록 증가 대비 **적응형 줌** — 30개 이하면 기록당 점 1개, 넘으면 **월당 점 1개**(색=그 달 평균 등급, 크기=기록 수 비례 12~22px, 클릭=해당 월 헤더로 스크롤)로 자동 전환. 데이터: '내 기록' 탭은 `fetchReviewsByUser`로 **전부 로드**해 리스트·여정 선·월 점프가 모두 일관(이전 `fetchMyJourney` 경량 쿼리는 전체 로드로 대체·폐기). '전체' 탭만 페이지네이션 유지. 줌아웃에서 미로드 월 클릭 불가 한계는 전체 로드로 해소(PR #67). 대량 기록 시 타임라인 가상화는 후속.
- 여정 요약 리디자인: 퍼센트 막대(`TrailSummary`)는 "여정" 정체성과 어긋나 폐기 → **여정 선(`TrailPath`)** 으로 교체. 가로 선 위에 기록이 시간순(왼쪽=과거)으로 등급 색 점으로 찍히고(실패=빈 링, 경계 단계=그라데이션), 월 단위 그룹에 월 라벨 표시. **점 클릭 시 해당 로그로 smooth 스크롤**(`#log-<id>` 앵커). 첫 진입 시 최신 구간(오른쪽 끝)이 보이게 자동 스크롤. 타임라인 리스트에도 **월 구분 헤더**(YYYY.MM + 점선) 추가, 월 단위로 레일 분절 — 단 꽃길순/흙길순 정렬에서는 월 구분 자동 숨김.
- 전체 탭 카드 리디자인(v3): "포스터 없음" 회색 플레이스홀더가 카드마다 좌측 1/3을 차지해 칙칙 → 포스터는 **있을 때만 렌더**(없으면 본문 풀폭)로 변경. 좌측 스파인을 성공/실패 색이 아니라 **'길' 등급 색**(경계 단계 그라데이션)으로 바꿔 포스터 없이도 색 정체성 확보(성공/실패는 우상단 뱃지로 유지). v2 잔재인 모노 시리얼(#NNNN)은 카드에서 제거.
- 탈출 속도 뱃지(반갈죽/삼갈죽): 빠른 탈출 은어를 자동 뱃지로. 반갈죽=제한시간 절반 이상 남기고 탈출, 삼갈죽=2/3 이상. `Room`에 제한시간 컬럼이 없어 **표준 60분 가정**(`escape-badge.ts` ASSUMED_LIMIT_MIN). 성공+남은 시간에서만 파생, 카드·상세·타임라인에 표시(`SpeedBadge`). 정밀화하려면 후속으로 `rooms.time_limit_min` 추가.
- rating 정규화 방어: 과거 별점 입력의 소수(4.5)·numeric 문자열이 들어오면 라벨(`===` 비교)과 색(`>=` 비교) 판정이 갈라져 "흙길 라벨 + 핑크 색" 버그 발생 → `normalizeRating`(반올림+1~5 클램프)을 모든 파생 함수 입구에 적용. 4.5는 5(꽃길)로 표시되며, 재방문 의사가 있으면 인생테마 조건도 충족.
- 경계 단계 그라데이션: 흙풀길(2)=갈색→초록, 풀꽃길(4)=초록→핑크 그라데이션으로 "사이 단계"임을 색으로 표현(`getTrailStepColor`/`getTrailStepSoftColor`). 작성 폼 디딤돌은 각 돌이 자기 단계 색을 가져 트랙 전체가 흙→꽃 여정으로 읽힘. 칩·도트·타임라인 노드에 동일 적용. 3버킷 집계(요약 바·필터)는 단색 유지.
- 등급 필터 UX: "흙풀길 이상" 식 임계값 드롭다운은 비직관적이라 기각. **3버킷(꽃길/풀길/흙길) 다중 토글 칩**으로 교체 — 색 도트 + 쉬운 말 병기("꽃길 재밌었어요")로 용어를 모르는 사용자도 즉시 이해. 작성 폼 디딤돌에도 단계별 쉬운 말 힌트("풀꽃길 · 재밌었어요") 표시. 쉬운 말 매핑은 `trail-grade.ts`의 `hint` 필드가 SSOT.
- 별점 전면 폐기 → "길" 체계로 통일: `rating`(1~5)과 1:1인 **5단계 사다리(흙길/흙풀길/풀길/풀꽃길/꽃길)** 를 도입해 입력(작성 폼 디딤돌 선택)·표시(카드/상세/타임라인 칩+도트)·필터("풀길 이상" 등)·정렬(꽃길순/흙길순)·통계(길 분포, 평균 길) 전부 교체. 보조지표(1~5)는 길 의미가 아니므로 별 대신 세그먼트 바 입력(`shared/ui/LevelSelect`). `StarRating` 컴포넌트·`--color-star` 토큰 삭제. DB는 `overall_rating` 그대로.
- 재미 등급("길") 표시 체계 도입: 방탈출 업계 은어를 차용해 `rating`(1~5)을 **꽃길(4~5)/풀길(3)/흙길(1~2)** 3단계로 표시. **5점 + 재방문 의사 → 인생테마**(꽃길 특별형). 신규 DB 컬럼 없이 `rating`에서 파생하는 순수 로직(`entities/review/lib/trail-grade.ts`가 SSOT). 목록의 "내 기록" 탭은 이 등급으로 색을 입힌 **여정 타임라인**으로 표현, "전체" 탭은 카드 구조를 유지하되 등급 칩만 공통 적용(성공/실패 시각은 그대로 유지).
