# UX 라이팅 가이드 (Escape-Log)

서비스의 모든 멘트·문구는 **토스 보이스&톤**을 기준으로 작성한다.
횡단 공통 문구는 [`src/shared/lib/messages.ts`](../src/shared/lib/messages.ts)에 중앙화한다.

---

## 1. 보이스 & 톤 7원칙

| 원칙 | 의미 | 예시 |
|------|------|------|
| 쉽게 | 한자어·외래어·전문용어 줄이기 | `HEADCOUNT` → "인원" |
| 간결하게 | 군더더기 제거, 핵심만 | "~하는 데 실패했습니다" → "~하지 못했어요" |
| 친근하게 | 해요체로 통일 | "삭제하시겠습니까?" → "삭제할까요?" |
| 행동 중심 버튼 | 버튼만 봐도 결과를 알게 | "확인" → "삭제하기" |
| 정직하게 | 에러를 사용자 탓 X, 다음 행동 제시 | "실패했습니다" → "잠시 후 다시 시도해 주세요" |
| 일관성 | 같은 개념엔 같은 단어 | 아래 용어 사전 준수 |
| 구체적으로 | 숫자·맥락 명시 | "삭제할 수 없습니다" → "리뷰 3개가 연결돼 있어 지울 수 없어요" |

---

## 2. 용어 사전 (필수)

| 개념 | 확정 용어 | 쓰지 않는 표현 |
|------|----------|---------------|
| 다녀온 공간 | **테마** | 방, 룸 |
| 업체·매장 | **지점** | 매장, 업체 |
| 작성물 | **리뷰** | 후기(감성 카피 제외) |
| 사진(첨부) | **사진** | 이미지 |
| 대표 이미지 | **포스터** | 썸네일 |

---

## 3. 문장 규칙

- **존댓말은 해요체로 통일.** `~합니다`, `~하십시오`, `~하시겠습니까` 금지.
- **에러**: 무엇이 안 됐는지 + 다음 행동. "~하지 못했어요. 다시 시도해 주세요."
- **버튼**: 동사+결과. "확인" 대신 "삭제하기", "등록" 대신 "이 테마 추가하기".
- **토스트**: 완료는 "~했어요", 실패는 "~하지 못했어요".
- **확인 다이얼로그**: 제목은 질문형("이 리뷰를 삭제할까요?"), 본문은 결과 안내("한 번 지우면 되돌릴 수 없어요").
- **빈 상태**: 공감 한 줄 + 다음 행동 유도.
- 마침표는 안내문에는 쓰되, 짧은 제목·라벨·버튼에는 생략.

---

## 4. 컨셉 라벨 처리

기존 터미널 컨셉의 영어 대문자 라벨(`LOG · ENTRY`, `METRICS`, `CLEAR/FAIL` 등)은
**전면 토스화** 방침에 따라 쉬운 한국어로 교체한다.

| 기존 | 변경 |
|------|------|
| `LOG · ENTRY` / `LOG · NEW` | 리뷰 상세 / 새 리뷰 (또는 키커 제거) |
| `METRICS · 평가 지표` | 세부 평가 |
| `VISIT · 방문 정보` | 방문 정보 |
| `BODY · 본문` | 후기 |
| `HEADCOUNT / REMAINING / REVISIT / VISITED` | 인원 / 남은 시간 / 재방문 / 방문일 |
| `CLEAR / FAIL` | 성공 / 실패 |
| `SPOILER · LOCKED` | 스포일러 |
| `STEP` | 단계 |

---

## 5. 가드레일

- 정책 페이지(약관/개인정보) **법률 본문**은 의미 훼손 위험이 있어 톤만 최소 손질, 내용은 유지.
- 접근성 텍스트(`aria-label`, `alt`)도 같은 기준으로 자연스럽게 정리.
- 새 문구 추가 시에도 이 가이드를 따르고, 여러 화면이 공유하면 `messages.ts`에 추가.
